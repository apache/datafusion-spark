#### `abs`

Returns the absolute value of `expr`, with the same type as the input. Unlike DataFusion's `abs`, which always errors on overflow, the result for the minimum value of a signed integer type (for example `-2147483648` for INT) depends on ANSI mode: with `datafusion.execution.enable_ansi_mode` off it is returned unchanged, and with it on the function fails with `ARITHMETIC_OVERFLOW`. Returns NULL if the input is NULL and NaN if it is NaN, and the absolute value of -0.0 is 0. Spark's interval types are not supported yet.

```sql
abs(expr)
```

##### Arguments

- **expr**: Numeric expression: integer, floating-point or decimal. NULL returns NULL.

##### Example

```sql
> SELECT abs(-1);
1
> SELECT abs(-99999999.99::DECIMAL(10, 2));
99999999.99
> SELECT abs((-2147483648)::INT);
-2147483648
```

#### `atan2`

Returns the angle in radians, between -pi and pi, between the positive x-axis and the point (`exprX`, `exprY`). Note that the y coordinate comes first. Both arguments are cast to DOUBLE and the result is a DOUBLE. Returns NULL if either input is NULL, and NaN if either input is NaN (and neither is NULL). Infinite inputs and signed zeros follow `java.lang.Math.atan2`: for example `atan2(-0.0, -1.0)` is -pi.

```sql
atan2(exprY, exprX)
```

##### Arguments

- **exprY**: Numeric y coordinate, cast to DOUBLE. NULL returns NULL.
- **exprX**: Numeric x coordinate, cast to DOUBLE. NULL returns NULL.

##### Example

```sql
> SELECT atan2(1, 1);
0.785398163397448
> SELECT atan2(0, -1);
3.141592653589793
> SELECT atan2(-0.0::double, -1.0::double);
-3.141592653589793
```

#### `bin`

Returns the binary representation of `expr` as a string, with no leading zeros. DataFusion has no built-in `bin`. The input is cast to BIGINT first, so fractional values are truncated and every negative value is rendered as its 64-bit two's complement, whatever its original integer width. Returns NULL if the input is NULL.

```sql
bin(expr)
```

##### Arguments

- **expr**: Numeric expression, cast to BIGINT. NULL returns NULL.

##### Example

```sql
> SELECT bin(13);
1101
> SELECT bin(13.3);
1101
> SELECT bin(-13);
1111111111111111111111111111111111111111111111111111111111110011
```

#### `bit_count`

Returns the number of bits that are set in `expr`, as an INT. As in Spark, signed integers are sign-extended to 64 bits before counting, so a negative value of any signed type counts the extra high bits (`bit_count(-1)` is 64 for TINYINT, SMALLINT, INT and BIGINT). Unsigned integers are counted at their own width. A boolean counts as 1 for true and 0 for false. NULL returns NULL. DataFusion has no built-in `bit_count`.

```sql
bit_count(expr)
```

##### Arguments

- **expr**: Boolean or integer expression (signed or unsigned, 8 to 64 bits). NULL returns NULL.

##### Example

```sql
> SELECT bit_count(7);
3
> SELECT bit_count(-1::int);
64
> SELECT bit_count(NULL::int);
NULL
```

#### `bit_get`

Returns the bit (0 or 1) at position `pos` of an integer, as a TINYINT. Positions count from 0 at the least significant bit. Returns NULL if either input is NULL. Errors if `pos` is negative or not less than the bit width of the type of `expr`. Integer literals are BIGINT in DataFusion but INT in Spark, so for an uncast literal the limit is 64 here and 32 in Spark. DataFusion has no built-in `bit_get`.

```sql
bit_get(expr, pos)
```

##### Arguments

- **expr**: Integer expression. NULL returns NULL.
- **pos**: Integer bit position, from 0 to the bit width of `expr` minus 1. Any other value is an error. NULL returns NULL.

##### Example

```sql
> SELECT bit_get(11, 0);
1
> SELECT bit_get(11, 2);
0
> SELECT bit_get(11, NULL);
NULL
```

##### Alternative Syntax

```sql
getbit(expr, pos)
```

- getbit

#### `bitwise_not`

Returns the bitwise NOT of a signed integer, with every bit flipped, in the same type as the input. In two's complement this is `-expr - 1`, and it never overflows (`bitwise_not` of the maximum value is the minimum value). NULL returns NULL. Spark SQL spells this `~expr`. DataFusion has no built-in `bitwise_not` function.

```sql
bitwise_not(expr)
```

##### Arguments

- **expr**: TINYINT, SMALLINT, INT or BIGINT expression. NULL returns NULL.

##### Example

```sql
> SELECT bitwise_not(0::int);
-1
> SELECT bitwise_not(-3::int);
2
> SELECT bitwise_not(2147483647::int);
-2147483648
```

```sql
> SELECT ceil(1.50::DECIMAL(10, 2));

> SELECT ceil(5::INT);
```

#### `rint`

```sql
rint(expr)
```

##### Arguments

- **expr**: Numeric expression. NULL returns NULL.

##### Example

```sql
> SELECT rint(12.3456);

> SELECT rint(2.5);

> SELECT rint(3.5);

```

#### `round`

Rounds `expr` to `scale` decimal places, rounding halves away from zero (HALF_UP: 2.5 becomes 3, -2.5 becomes -3). A negative `scale` rounds to the left of the decimal point, so `round(25, -1)` is 30. The result has the same type as `expr`: integers stay integers, and decimals keep their precision and scale (`round(2.345::DECIMAL(10, 3), 2)` is 2.350), where Spark and DataFusion's `round` reduce the decimal scale (Spark returns 2.35 as DECIMAL(10, 2); see [#37](https://github.com/apache/datafusion-spark/issues/37)). Integer overflow depends on ANSI mode: with `datafusion.execution.enable_ansi_mode` off the result wraps around (`round(2147483647, -1)` is -2147483646), and with it on the function fails with an overflow error. A `scale` beyond the precision of the value returns the value unchanged for positive `scale` and 0 for negative `scale`. Infinity and NaN are returned unchanged. Returns NULL if `expr` or `scale` is NULL. Strings, booleans and timestamps are rejected.

```sql
round(expr[, scale])
```

##### Arguments

- **expr**: Numeric expression: integer, floating-point or decimal. NULL returns NULL.
- **scale**: Optional constant integer number of decimal places. Defaults to 0. A negative value rounds to the left of the decimal point. NULL returns NULL.

##### Example

```sql
> SELECT round(2.5::DOUBLE);
3
> SELECT round(2.345::DOUBLE, 2);
2.35
> SELECT round(25, -1);
30
> SELECT round(2.345::DECIMAL(10, 3), 2);
2.350
```

#### `shiftleft`

Shifts the bits of `expr` left by `n` positions. Bits shifted past the top are lost, so the result can change sign or wrap to 0. As in Spark (and Java), the shift amount is taken modulo the bit width of `expr` (32 for INT, 64 for BIGINT), so `shiftleft(1::int, 32)` is 1 and a negative `n` shifts by the bit width plus `n`. TINYINT and SMALLINT are widened to INT, and the result has the type of the widened `expr`. Returns NULL if either input is NULL. DataFusion has no built-in `shiftleft` function.

```sql
shiftleft(expr, n)
```

##### Arguments

- **expr**: Integer expression to shift. NULL returns NULL.
- **n**: Integer number of bit positions, taken modulo the bit width of `expr`. NULL returns NULL.

##### Example

```sql
> SELECT shiftleft(2::int, 1);
4
> SELECT shiftleft(2147483647::int, 1);
-2
> SELECT shiftleft(1::int, 32);
1
```

#### `shiftright`

Shifts the bits of `expr` right by `n` positions, copying the sign bit into the vacated high bits (an arithmetic shift, so negative values stay negative). As in Spark (and Java), the shift amount is taken modulo the bit width of `expr` (32 for INT, 64 for BIGINT), so `shiftright(1::int, 32)` is 1 and a negative `n` shifts by the bit width plus `n`. TINYINT and SMALLINT are widened to INT, and the result has the type of the widened `expr`. Returns NULL if either input is NULL. See `shiftrightunsigned` for a shift that fills with zeros. DataFusion has no built-in `shiftright` function.

```sql
shiftright(expr, n)
```

##### Arguments

- **expr**: Integer expression to shift. NULL returns NULL.
- **n**: Integer number of bit positions, taken modulo the bit width of `expr`. NULL returns NULL.

##### Example

```sql
> SELECT shiftright(16::int, 3);
2
> SELECT shiftright(-16::int, 3);
-2
> SELECT shiftright(4::int, -1);
0
```

#### `shiftrightunsigned`

Shifts the bits of `expr` right by `n` positions, filling the vacated high bits with zeros (a logical shift, Java's `>>>`), so a negative value becomes a large positive one. As in Spark (and Java), the shift amount is taken modulo the bit width of `expr` (32 for INT, 64 for BIGINT), so `shiftrightunsigned(1::int, 32)` is 1 and a negative `n` shifts by the bit width plus `n`. TINYINT and SMALLINT are widened to INT, and the result has the type of the widened `expr`. Returns NULL if either input is NULL. DataFusion has no built-in `shiftrightunsigned` function.

```sql
shiftrightunsigned(expr, n)
```

##### Arguments

- **expr**: Integer expression to shift. NULL returns NULL.
- **n**: Integer number of bit positions, taken modulo the bit width of `expr`. NULL returns NULL.

##### Example

```sql
> SELECT shiftrightunsigned(16::int, 3);
2
> SELECT shiftrightunsigned(-16::int, 3);
536870910
```

#### `unhex`

Converts a string of hexadecimal digits to BINARY: each pair of digits becomes one byte. This is the inverse of `hex`. DataFusion has no built-in `unhex`. Digits may be upper or lower case. A string with an odd number of digits is treated as if it had a leading `0`. Returns NULL if the input is NULL or contains anything other than hex digits (including spaces), and an empty BINARY value for an empty string.

```sql
unhex(str)
```

##### Arguments

- **str**: String expression of hexadecimal digits. NULL returns NULL.

##### Example

```sql
> SELECT arrow_cast(unhex('537061726B2053514C'), 'Utf8');
Spark SQL
> SELECT unhex('ABC');
0abc
> SELECT unhex('GGHH');
NULL
```

#### `width_bucket`

Returns the number of the bucket that `expr` falls into, when the range from `min` to `max` is split into `num_buckets` buckets of equal width. DataFusion has no built-in `width_bucket`. Buckets are numbered from 1. A value before the range returns 0, and a value at or beyond the end of the range returns `num_buckets + 1`. `min` may be greater than `max`, in which case buckets count down from `min`. Works on numbers (cast to DOUBLE), durations and intervals. Returns NULL if any input is NULL, if `num_buckets` is 0 or less, if `min` equals `max`, if a number is NaN or infinite, or if an interval mixes months with days or smaller units.

```sql
width_bucket(expr, min, max, num_buckets)
```

##### Arguments

- **expr**: Numeric, duration or interval value to place in a bucket. NULL returns NULL.
- **min**: Start of the range, of the same kind as `expr`. NULL returns NULL.
- **max**: End of the range, of the same kind as `expr`. NULL returns NULL.
- **num_buckets**: Integer number of buckets. 0 or less, or NULL, returns NULL.

##### Example

```sql
> SELECT width_bucket(5.3, 0.2, 10.6, 5);
3
> SELECT width_bucket(-0.9, 5.2, 0.5, 2);
3
> SELECT width_bucket(8.1, 0.0, 5.7, 4);
5
> SELECT width_bucket(INTERVAL '1' DAY, INTERVAL '0' DAY, INTERVAL '10' DAY, 10);
2
```

#### `if`

Returns `expr1` if `cond` is true, and `expr2` otherwise. A NULL condition counts as false. It is rewritten to `CASE WHEN cond THEN expr1 ELSE expr2 END`, so an error such as division by zero in the branch that isn't taken is not raised. `expr1` and `expr2` are coerced to a common type (`if(true, 10, 20.5)` returns a DOUBLE). It is an error if `cond` is not a boolean or NULL. DataFusion has no built-in `if`.

```sql
if(cond, expr1, expr2)
```

##### Arguments

- **cond**: Boolean expression. NULL is treated as false.
- **expr1**: Expression returned when `cond` is true.
- **expr2**: Expression returned when `cond` is false or NULL.

##### Example

```sql
> SELECT if(1 < 2, 'a', 'b');
a
> SELECT if(NULL, 'yes', 'no');
no
> SELECT if(true, 1 / 1, 1 / 0);
1
```

#### `ascii`

Returns the numeric code point of the first character of `str`. Despite the name, this is the full Unicode code point, not just ASCII (`ascii('😀')` is 128512). An empty string returns 0, and NULL returns NULL. Unlike DataFusion's `ascii`, numeric input is accepted and cast to a string first, so `ascii(2)` is the code point of `'2'`.

```sql
ascii(str)
```

##### Arguments

- **str**: String expression. Numeric values are cast to a string. NULL returns NULL.

##### Example

```sql
> SELECT ascii('Spark');
83
> SELECT ascii('');
0
> SELECT ascii(2);
50
```

#### `char`

Returns the character whose code point is `n` modulo 256, so `char(321)` is `A`. A negative `n` returns an empty string, and NULL returns NULL. DataFusion's `chr` instead uses `n` as a full Unicode code point and errors on negative or invalid values.

```sql
char(n)
```

##### Arguments

- **n**: Integer expression, cast to BIGINT. NULL returns NULL.

##### Example

```sql
> SELECT char(65);
A
> SELECT char(321);
A
> SELECT char(-1);
-- empty string
```

#### `concat`

Concatenates the arguments into a single string, or binary if all arguments are binary. Returns NULL if any argument is NULL, whereas DataFusion's `concat` skips NULL arguments. Unlike DataFusion's `concat`, it also accepts zero arguments and then returns an empty string.

```sql
concat([expr1[, ..., exprN]])
```

##### Arguments

- **expr**: String or binary expressions to concatenate. Any NULL makes the result NULL.

##### Example

```sql
> SELECT concat('Spark', 'SQL');
SparkSQL
> SELECT concat('Spark', 'SQL', NULL);
NULL
> SELECT concat();
-- empty string
```

#### `concat_ws`

Concatenates the arguments after the first, separated by `sep`. NULL arguments and NULL array elements are skipped, so if every argument is NULL the result is an empty string. A NULL separator returns NULL. With only a separator, the result is an empty string. Unlike DataFusion's `concat_ws`, array arguments are expanded into their elements, non-string arguments (numbers, booleans, dates, binary, array elements) are cast to strings, and the result is always `Utf8`.

```sql
concat_ws(sep[, expr1[, ..., exprN]])
```

##### Arguments

- **sep**: Separator, cast to a string. NULL returns NULL.
- **expr**: Values or arrays to join. Arrays contribute each element. NULL values and elements are skipped. Structs are not supported.

##### Example

```sql
> SELECT concat_ws(' ', 'Spark', 'SQL');
Spark SQL
> SELECT concat_ws('/', 'foo', NULL, 'bar');
foo/bar
> SELECT concat_ws(',', 'x', array('a', 'b'), 'y');
x,a,b,y
> SELECT concat_ws(NULL, 'a', 'b');
NULL
```

#### `elt`

Returns the `n`-th of the following arguments as a string (1-based). DataFusion has no built-in `elt`. A NULL `n` returns NULL, as does picking a NULL argument. If `n` is less than 1 or greater than the number of arguments, the result is NULL, or an error when `datafusion.execution.enable_ansi_mode` is true.

```sql
elt(n, expr1[, ..., exprN])
```

##### Arguments

- **n**: Integer index, 1-based, cast to BIGINT. NULL returns NULL.
- **expr**: At least one value to choose from. Each is cast to a string.

##### Example

```sql
> SELECT elt(1, 'scala', 'java');
scala
> SELECT elt(2, 'a', 1);
1
> SELECT elt(3, 'scala', 'java');
NULL
```

#### `format_string`

Returns a string formatted from a printf-style format string, following Java's `java.util.Formatter` as Spark does. DataFusion has no built-in equivalent. Supports the `%s`, `%b`, `%c`, `%d`, `%o`, `%x`, `%e`, `%f`, `%g`, `%a` and `%t` (date/time) conversions and their uppercase forms, the `-`, `+`, ` `, `0`, `#`, `,` and `(` flags, width and precision, and positional (`%2$s`) and relative (`%<s`) argument references. A NULL format string returns NULL, while a NULL argument is formatted as `null`. It is an error if there are too few arguments or an argument does not fit its conversion. `%h` and `%H` (hash code) are not supported and return an error.

```sql
format_string(format[, arg1[, ..., argN]])
```

##### Arguments

- **format**: String format specification. NULL returns NULL.
- **arg**: Values to format. Each must suit the conversion that refers to it. A NULL value is formatted as `null`.

##### Example

```sql
> SELECT format_string('Hello World %d %s', 100, 'days');
Hello World 100 days
> SELECT format_string('%2$s %1$d', 42, 'test');
test 42
> SELECT format_string('Precision: %.2f', 3.14159);
Precision: 3.14
> SELECT format_string('Value: %s', NULL);
Value: null
```

##### Alternative Syntax

```sql
printf(format[, arg1[, ..., argN]])
```

#### `ilike`

Returns true if `str` matches `pattern`, ignoring case. In the pattern, `_` matches any one character and `%` matches any sequence of characters. Returns NULL if either argument is NULL. #### `substr`

_Alias of [substring](#substring)._

#### `substring`

Returns the substring of `str` that starts at `pos` and is `length` characters long. Positions are 1-based and count characters (bytes for binary input). A position of 0 is treated as 1. A negative position counts from the end of the string (-1 is the last character). If it reaches past the start, the part before the start comes off `length` (so `substring('abc', -10, 3)` is empty). A position past the end, or a length of 0 or less, returns an empty string, and a length that runs past the end is clamped. Returns NULL if any input is NULL. DataFusion's `substr` also takes the part before the start off `length`, but counts positions below 1 from the start instead of the end (0 is one before the first character, -1 two before), so `substring('abc', -3, 6)` returns `abc`, where DataFusion's `substr('abc', -3, 6)` returns `ab`.

```sql
substring(str, pos[, length])
```

##### Arguments

- **str**: String or binary expression. For binary input, positions count bytes.
- **pos**: Integer start position, 1-based. 0 is treated as 1. A negative value counts from the end of the string.
- **length**: Optional integer maximum length. If omitted, the rest of the string is returned. A value of 0 or less returns an empty string.

##### Example

```sql
> SELECT substring('Spark SQL', 5);
k SQL
> SELECT substring('Spark SQL', -3);
SQL
> SELECT substring('Spark SQL', 0);
Spark SQL
> SELECT substring('Spark SQL', 3, 0);
-- empty string
> SELECT substring('Spark SQL', NULL);
NULL
```

##### Alternative Syntax

```sql
substr(str, pos[, length])
```

- substr

#### `base64`

Encodes binary as a padded base64 string, using the standard alphabet. It is the same as DataFusion's `encode(expr, 'base64pad')`; DataFusion's `encode(expr, 'base64')` leaves out the padding. String input is encoded as its UTF-8 bytes. Returns NULL if the input is NULL.

```sql
base64(bin)
```

##### Arguments

- **bin**: Binary or string expression to encode. NULL returns NULL.

##### Example

```sql
> SELECT base64('Spark SQL');
U3BhcmsgU1FM
> SELECT base64('Spark S');
U3BhcmsgUw==
```

#### `encode`

Encodes a string into binary using a character set. Unlike DataFusion's `encode`, which takes `base64` or `hex` and returns a string, this takes a character set and returns binary. Supported character sets are `US-ASCII`, `ISO-8859-1`, `UTF-8`, `UTF-16`, `UTF-16BE`, `UTF-16LE`, `UTF-32`, `UTF-32BE` and `UTF-32LE`, matched case-insensitively, and the aliases `ASCII`, `LATIN1`, `ISO88591` and the spellings without a hyphen (`UTF8`, `UTF16BE`, ...). Any other character set is an error. `UTF-16` writes a big-endian byte order mark first. `UTF-32` is big-endian with no byte order mark. Characters the character set cannot represent (non-ASCII in `US-ASCII`, code points above U+00FF in `ISO-8859-1`) are replaced with `?`. Binary input is decoded as UTF-8 first, with each invalid byte replaced by U+FFFD. Returns NULL if either input is NULL. This follows Spark 3.5. Spark 4.0 rejects the aliases and raises an error on characters it cannot represent, unless `spark.sql.legacy.javaCharsets` and `spark.sql.legacy.codingErrorAction` are set; those settings are not supported yet.

```sql
encode(str, charset)
```

##### Arguments

- **str**: String or binary expression to encode. Binary input is decoded as UTF-8, with invalid bytes replaced by U+FFFD. NULL returns NULL.
- **charset**: String name of the character set, matched case-insensitively. May vary per row. NULL returns NULL.

##### Example

```sql
> SELECT encode('Spark SQL', 'utf-8');
537061726b2053514c
> SELECT encode('AB', 'utf-16le');
41004200
> SELECT encode('é', 'us-ascii');
3f
```

#### `to_binary`

Converts a string to binary using the given format. DataFusion has no built-in `to_binary`. `hex` decodes hex digits, and an odd number of digits is padded with a leading zero. `utf-8` (or `utf8`) returns the string's UTF-8 bytes. `base64` decodes like Java's MIME decoder, as Spark does: padding is optional and characters outside the base64 alphabet are skipped. An empty string converts to empty binary in every format. A value that cannot be converted, or a format that is not recognised, is an error; use `try_to_binary` to get NULL instead. Returns NULL if either input is NULL.

```sql
to_binary(str[, fmt])
```

##### Arguments

- **str**: String expression to convert. NULL returns NULL.
- **fmt**: Optional constant string format, matched case-insensitively: `hex` (the default), `utf-8`, `utf8` or `base64`. A NULL format returns NULL.

##### Example

```sql
> SELECT to_binary('537061726b');
537061726b
> SELECT to_binary('abc', 'utf-8');
616263
> SELECT to_binary('U3Bhcms', 'base64');
537061726b
```

#### `try_to_binary`

Same as `to_binary`, except that a value which cannot be converted returns NULL for that row, and a format that is not recognised returns NULL, instead of an error. DataFusion has no built-in `try_to_binary`.

```sql
try_to_binary(str[, fmt])
```

##### Arguments

- **str**: String expression to convert. NULL, or a value that cannot be converted, returns NULL.
- **fmt**: Optional constant string format, matched case-insensitively: `hex` (the default), `utf-8`, `utf8` or `base64`. A NULL or unrecognised format returns NULL.

##### Example

```sql
> SELECT try_to_binary('U3Bhcms=', 'base64');
537061726b
> SELECT try_to_binary('zz', 'hex');
NULL
> SELECT try_to_binary('abc', 'invalidFormat');
NULL
```

#### `unbase64`

Decodes a base64 string to binary, the same way as Java's MIME decoder, which Spark uses. DataFusion has no built-in `unbase64`. Padding is optional, and characters outside the base64 alphabet (such as spaces and line breaks) are skipped. A single leftover character at the end, malformed padding, or base64 characters after the padding are errors. Returns NULL if the input is NULL.

```sql
unbase64(str)
```

##### Arguments

- **str**: String or binary expression holding base64 text. NULL returns NULL.

##### Example

```sql
> SELECT arrow_cast(unbase64('U3BhcmsgU1FM'), 'Utf8');
Spark SQL
> SELECT arrow_cast(unbase64('YW Jj'), 'Utf8');
abc
> SELECT hex(unbase64('123'));
D76D
```

#### `from_utc_timestamp`

Treats `ts` as a UTC wall-clock time and returns the wall-clock time in time zone `tz`. DataFusion has no built-in equivalent. A string `ts` is cast to a timestamp, so a string with an offset is first converted to UTC. The result has the same type as `ts`, including any time zone it carries. Returns NULL if either argument is NULL. `tz` accepts Spark's spellings: region IDs, offsets such as `+01:00`, `GMT+1`, `UTC+1:2` and `UT-010203`, Java short IDs such as `PST`, and legacy `SystemV/` IDs. An offset beyond 18 hours or an unknown zone is an error. Differences from Spark: `tz` is only parsed for rows where both arguments are non-NULL, so an invalid constant `tz` can return NULL where Spark raises an error; conversion is limited to Chrono's calendar range, which is narrower than the range Spark implements but covers Spark's documented range; and region rules from `chrono-tz` may differ after 2099, because it does not extrapolate later daylight saving time transitions.

```sql
from_utc_timestamp(ts, tz)
```

##### Arguments

- **ts**: Timestamp expression, interpreted as UTC. A string is cast to a timestamp. NULL returns NULL.
- **tz**: String time zone to convert to. NULL returns NULL.

##### Example

```sql
> SELECT from_utc_timestamp('2016-08-31'::timestamp, 'Asia/Seoul');
2016-08-31T09:00:00
> SELECT from_utc_timestamp('2018-03-13T06:18:23+02:00', 'America/New_York');
2018-03-13T00:18:23
> SELECT from_utc_timestamp('2024-07-01T00:00:00'::timestamp, 'GMT+1');
2024-07-01T01:00:00
> SELECT from_utc_timestamp('2016-08-31'::timestamp, NULL);
NULL
```

#### `make_dt_interval`

Returns a day-time interval built from days, hours, minutes and seconds. DataFusion has no built-in equivalent. All arguments are optional from the right and default to 0, so `make_dt_interval()` is a zero interval. Components can be negative and are added together, so `make_dt_interval(1, -24)` is zero. The result is a `Duration(Microsecond)` rather than an Arrow interval, because Arrow's day-time interval only has millisecond precision while Spark's has microsecond precision. Returns NULL if any argument is NULL or `secs` is NaN or infinite. Overflow returns NULL, where Spark raises an error ([#20](https://github.com/apache/datafusion-spark/issues/20)). Because hours and minutes are added up in 32-bit integers, more than 1,491,308 days also returns NULL, although Spark returns the interval ([#109](https://github.com/apache/datafusion-spark/issues/109)). Unlike Spark, where `secs` is a DECIMAL(18, 6), `secs` is cast to DOUBLE and the fraction is rounded to microseconds.

```sql
make_dt_interval([days[, hours[, mins[, secs]]]])
```

##### Arguments

- **days**: Integer number of days, cast to INT. NULL returns NULL.
- **hours**: Integer number of hours, cast to INT. NULL returns NULL.
- **mins**: Integer number of minutes, cast to INT. NULL returns NULL.
- **secs**: Numeric number of seconds, which may have a fraction, cast to DOUBLE. NULL, NaN or an infinite value returns NULL.

##### Example

```sql
> SELECT make_dt_interval(1, 12, 30, 1.001001);
1 days 12 hours 30 mins 1.001001 secs
> SELECT make_dt_interval(2);
2 days 0 hours 0 mins 0.000000 secs
> SELECT make_dt_interval(100, NULL, 3);
NULL
```

Returns NULL if any argument is NULL or `secs` is NaN or infinite. Overflow returns NULL; ANSI mode is not applied. Unlike Spark, where `secs` is a DECIMAL(18, 6), `secs` is cast to DOUBLE and the fraction is rounded to nanoseconds.


#### `to_utc_timestamp`

Treats `ts` as a wall-clock time in time zone `tz` and returns the UTC wall-clock time. This is the inverse of `from_utc_timestamp`. DataFusion has no built-in equivalent. A string `ts` is cast to a timestamp, so a string with an offset is first converted to UTC. The result has the same type as `ts`, including any time zone it carries. ##### Example

```sql

> SELECT to_utc_timestamp('2018-03-13T06:18:23+02:00', 'America/New_York');
2018-03-13T08:18:23
> SELECT to_utc_timestamp('2016-08-31'::timestamp, NULL);
NULL
```

#### `array`

Returns an array of the given elements, coerced to a common type. NULL elements are kept, and with no arguments the result is an empty array. Unlike DataFusion's `make_array`, the list's element field is named `element`, as in Spark, rather than `item`.


##### Example

```sql
> SELECT array(1, 2, 3);
[1, 2, 3]

[1, NULL, 3]

```

#### `array_repeat`

Returns an array that contains `element` `count` times. Unlike DataFusion's `array_repeat`, a NULL `count` returns NULL. A NULL `element` is repeated like any other value, and a `count` of 0 or less returns an empty array.

```sql
array_repeat(element, count)
```

##### Arguments

- **element**: Value to repeat, of any type. NULL is repeated.
- **count**: Integer number of times to repeat `element`. Non-integer types are an error. NULL returns NULL.

##### Example

```sql
> SELECT array_repeat('123', 2);
[123, 123]
> SELECT array_repeat(NULL, 2);
[NULL, NULL]
> SELECT array_repeat('123', NULL);
NULL
```

#### `shuffle`

Returns a random permutation of the array. DataFusion has no built-in `shuffle`. NULL elements are kept and shuffled with the others, and a NULL array returns NULL. With a `seed`, the order is the same on every run. It comes from a different random number generator than Spark's, so it does not match Spark's order for the same seed.

```sql
shuffle(array[, seed])
```

##### Arguments

- **array**: Array to shuffle. NULL returns NULL.
- **seed**: Optional constant integer seed. A NULL seed is the same as no seed, which gives a different order on each call.

##### Example

```sql
> SELECT shuffle(array(1, 2, 3, 4, 5, NULL), 1);
[1, 4, NULL, 2, 5, 3]
> SELECT shuffle(NULL);
NULL
```

#### `size`

Returns the number of elements in an array, or the number of entries in a map, as an INT. NULL elements are counted. DataFusion has no built-in `size`. A NULL input returns -1 whatever the ANSI mode setting, so the result is never NULL. This is Spark's legacy behavior (`spark.sql.legacy.sizeOfNull` true and ANSI mode off). Spark with ANSI mode on, the default since Spark 4.0, returns NULL instead.

```sql
size(expr)
```

##### Arguments

- **expr**: Array or map expression. NULL returns -1.

##### Example

```sql
> SELECT size(array(1, NULL, 3));
3
> SELECT size(map(array('a', 'b'), array(1, 2)));
2
> SELECT size(CAST(NULL AS ARRAY<INT>));
-1
```

#### `slice`

Returns the part of array `x` that starts at `start` and is at most `length` elements long. Unlike DataFusion's `array_slice`, the third argument is a length, not an end index. Positions are 1-based, and a negative `start` counts from the end of the array (-1 is the last element). A `start` past the end, or one that counts back past the first element, returns an empty array, and a `length` that runs past the end is clamped. A `start` of 0 or a negative `length` is an error. Returns NULL if any argument is NULL.

```sql
slice(x, start, length)
```

##### Arguments

- **x**: Array to slice. NULL returns NULL.
- **start**: Integer start position, 1-based. A negative value counts from the end of the array. 0 is an error.
- **length**: Integer maximum number of elements to return. A negative value is an error.

##### Example

```sql
> SELECT slice(array(1, 2, 3, 4), 2, 2);
[2, 3]
> SELECT slice(array(1, 2, 3, 4), -2, 2);
[3, 4]
> SELECT slice(array(1, 2, 3, 4), 100, 2);
[]
```

#### `equal_null`

Returns true if the two arguments are equal or both NULL, and false otherwise. Never returns NULL. Same as Spark's `<=>` operator and DataFusion's `IS NOT DISTINCT FROM`, which it is rewritten to. The arguments are coerced to a common type, so `equal_null(1::int, 1.0::double)` is true; it is an error if they can't be compared. For floating-point values NaN equals NaN and 0.0 equals -0.0, including inside arrays and structs. DataFusion has no built-in `equal_null`.

```sql
equal_null(expr1, expr2)
```

##### Arguments

- **expr1**: Expression of any comparable type.
- **expr2**: Expression of a type comparable with `expr1`.

##### Example

```sql
> SELECT equal_null(NULL, NULL);

```

#### `stack`

Separates `expr1`, ..., `exprk` into `n` rows of `ceil(k / n)` columns named `col0`, `col1`, ... The values fill the rows in order, and the last rows are padded with NULLs. DataFusion has no built-in `stack`. In Spark, `stack` is a generator that returns rows. A scalar function returns one value per row, so here the rows are returned as a list of structs, which the caller (e.g. Comet, or `unnest` in SQL) is expected to expand. As in Spark, the list is never NULL, but its elements and fields can be. As in Spark, `n` must be an INT from 1 to 2147483647, and the values of a column must have the same type, which is the type of its first non-NULL value. NULLs, Arrow types of the same Spark type (such as `Utf8` and `Utf8View`), and integer literals that fit an INT column are cast to it. Unlike Spark, which accepts any constant `n` (such as `3 - 1`), `n` must be an integer literal, because the return type is planned before expressions are folded. The rows are materialized, so a very large `n`, such as `stack(2000000000, 1)`, is an error.

```sql
stack(n, expr1[, ..., exprk])
```

##### Arguments

- **n**: Integer literal number of rows, from 1 to 2147483647.
- **expr**: One or more values to separate into rows. The values of each column must have the same type.

##### Example

```sql
> SELECT stack(2, 1, 2, 3);
[{col0: 1, col1: 2}, {col0: 3, col1: NULL}]
> SELECT unnest(stack(2, 'a', 1, 'b', 2));
{col0: a, col1: 1}
{col0: b, col1: 2}
```

```sql
url_encode(str)
```

#### `avg`

Returns the average of the non-NULL values as a DOUBLE, or NULL if there are none. All numeric input is cast to DOUBLE first. So unlike DataFusion's `avg` and Spark's, DECIMAL input returns a DOUBLE rather than a DECIMAL ([#111](https://github.com/apache/datafusion-spark/issues/111)).


##### Arguments

##### Example

```sql
> SELECT avg(a) FROM (VALUES (40), (23), (17), (40), (NULL)) AS t(a);
30
```

#### `collect_list`

Returns an array of the non-NULL values, including duplicates. Unlike DataFusion's `array_agg`, NULL values are skipped, so a group or window frame that is empty or holds only NULLs returns an empty array, where `array_agg` returns NULL or an array of NULLs. The order of the elements depends on the order of the rows, which may not be deterministic. `ORDER BY` inside the call is not supported and fails with an internal error ([#112](https://github.com/apache/datafusion-spark/issues/112)).

```sql
collect_list(expr)
```

##### Arguments

- **expr**: Expression of any type to collect. NULL values are skipped.

##### Example

```sql
> SELECT collect_list(a) FROM (VALUES (1), (2), (NULL), (1)) AS t(a);
[1, 2, 1]
> SELECT collect_list(a) FROM (VALUES (CAST(NULL AS INT))) AS t(a);
[]
```

#### `collect_set`

Returns an array of the distinct non-NULL values, in no particular order. Unlike DataFusion's `array_agg(DISTINCT ...)`, NULL values are skipped, so a group or window frame that is empty or holds only NULLs returns an empty array, where `array_agg` returns NULL or `[NULL]`.

```sql
collect_set(expr)
```

##### Arguments

- **expr**: Expression of any type to collect. NULL values are skipped.

##### Example

```sql
> SELECT array_sort(collect_set(a)) FROM (VALUES (1), (2), (NULL), (2)) AS t(a);
[1, 2]
> SELECT collect_set(a) FROM (VALUES (CAST(NULL AS INT))) AS t(a);
[]
```

#### `try_sum`

Returns the sum of the non-NULL values, or NULL if the sum overflows. DataFusion has no built-in `try_sum`. Integer input returns BIGINT, floating-point input returns DOUBLE, and DECIMAL(p, s) returns DECIMAL(min(p + 10, 38), s). BIGINT and DECIMAL overflow returns NULL, while DOUBLE sums follow IEEE 754 and can return Infinity or NaN. Returns NULL if all values are NULL. Other input types, such as intervals, are not supported.

```sql
try_sum(expr)
```

##### Arguments

- **expr**: Integer, floating-point or decimal expression to sum. NULL values are skipped.

##### Example

```sql
> SELECT try_sum(x) FROM VALUES (1), (2), (3) AS tab(x);
6
> SELECT try_sum(x) FROM VALUES (CAST(9223372036854775807 AS BIGINT)), (1) AS tab(x);
NULL
```
